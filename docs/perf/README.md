# DWES API performance benchmarks

Harness: [`scripts/benchmark-api.mjs`](../../scripts/benchmark-api.mjs).

## Methodology

- The harness spawns a dedicated compiled backend (`node dist/main.js` from
  `backend/`, `--spawn`) on port **3111** so measurements never mix with the
  interactive dev instance on 3001. `DWES_THROTTLE_LIMIT=100000` lifts the
  global rate limiter for the run (the env override exists only for load
  harnesses; the production default remains 120 req/min). The login endpoint
  keeps its real `10/min` `@Throttle` — login is measured with 5 paced
  iterations and role-token logins are budgeted to stay under the limit.
- Per endpoint: 10 warmup requests (fewer for heavy endpoints), then N
  sequential measured iterations. Recorded: min/mean/p50/p90/p95/p99/max
  latency, TTFB (first body chunk — meaningful for streamed files), status
  histogram (any unexpected status flags the run), last payload size.
- Concurrency: 10-way bursts × 5 rounds on the list, schedule, and PDF
  endpoints (5×3 for the 14.9 MB PDF).
- SSE: time from request start to the first heartbeat frame bytes, ×15.
- Uploads: synthetic in-memory XLSX (50 and 5000 rows, WRING_FRAME-shaped) to
  the parse-only `extract-metadata` endpoint; a synthetic 5 MB PDF uploaded to
  a disposable `DEMO_PROJECT_*` project (`npm run demo:setup` /
  `demo:teardown`) so real project data is never touched.
- Resource usage: the spawned backend PID is sampled every 2 s via
  `Get-Process` (cumulative CPU seconds + working set); the run records CPU
  delta, peak and mean RSS.
- **Same-data guarantee:** each run records a dataset fingerprint (project
  code, frame count, cable count, drawing count and byte size). `--compare`
  refuses a clean exit if fingerprints differ. Demo-project artifacts are
  excluded by design (fresh per run).
- Read benchmarks target the real project read-only
  (default `132KV33KV_KSA_RIYADH_2026_001`, 1 frame / 400 cables / one
  14.9 MB PDF GA drawing). No mutation endpoints are benchmarked outside the
  demo project.

## Runs

| File | What |
|---|---|
| `baseline-express.json` | Express adapter baseline (pre-migration) |
| `after-fastify.json` | Fastify adapter + optimization passes (post-migration) |
| `comparison.md` | Side-by-side p50/p95 generated by `--compare … --md` |

## Reproduce

```powershell
npm --prefix backend run build
npm run demo:setup   # note the DEMO_PROJECT_ code (needs supervisor creds via DWES_ADMIN_USER/PASS)
node scripts/benchmark-api.mjs --spawn --label my-run --out docs/perf/my-run.json --demo-code DEMO_PROJECT_...
npm run demo:teardown
node scripts/benchmark-api.mjs --compare docs/perf/baseline-express.json docs/perf/my-run.json --md docs/perf/comparison.md
```

Credentials are read from the private demo-account file
(`backend/seeds/demo-accounts.local.json`, untracked) via
`scripts/demo-account-loader.mjs`; no secrets appear in this directory.
